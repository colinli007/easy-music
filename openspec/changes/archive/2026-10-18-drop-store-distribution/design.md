## Context

动机见 proposal。与实现相关的现状：

- **CLA**：`.github/workflows/cla.yml` + `.github/scripts/cla.cjs`（白名单写死维护者账号）+ `cla.test.cjs`（`pnpm test:cla`），`main` 分支保护把 `CLA` 设为必需检查。`.github/` 下没有其他工作流。
- **许可证检查**：`tools/check-constraints.mjs` 用正则 `\b(A?GPL|LGPL)\b|SEE LICENSE` 拦依赖，另一半检查核心路径不引用插件实现模块。
- **iOS 裁剪**：`src/plugins/index.ts` 是 `supported: false` 的空实现门面，`index.android.ts` 转发到真实实现；`src/plugins/screens/` 下 7 个屏幕各有一个重定向到首页的空壳和一个 `.android.tsx` 真实实现。`pnpm check:ios-strip` 导出 iOS 产物断言其中没有插件代码。`eslint.config.js` 禁止插件目录外引用插件实现模块与插件专属依赖（`axios`、`cheerio` 等）。
- **依赖 `supported` 的地方**：`src/app/(tabs)/profile.tsx`（是否渲染「插件音源」入口）、`src/lyrics/ui/lyrics-card.tsx`（无歌词时的提示文案）。
- **版权行**：约 120 个文件的第二行 `// Copyright (C) 2026 li1164267803 · 轻松音乐 EasyMusic`，由 `tools/eslint-rules/gpl-header.js` 逐字校验。
- **iOS 侧的插件可行性**：插件宿主是纯 JS（与平台无关的 Hermes 执行），存储在应用文档目录；expo-audio 的 iOS 实现把请求头放进 `AVURLAssetHTTPHeaderFieldsKey`，插件给出的请求头与 UA 能传到播放引擎；插件文件安装用的 `File.pickFileAsync()` 两端相同且不限定类型。实现代码中没有其他 Android 专属调用。

## Goals / Non-Goals

**Goals:**

- 三条为上架设立的约束全部撤掉，且撤得干净：不留空壳文件、不留以「上架」「裁剪」为理由的注释与规则文案。
- 插件在 iOS 上以与 Android 相同的代码路径运行，没有平台分支。
- 文档如实描述现状：功能完成、两端可用、仅开源分发、如何获取。

**Non-Goals:**

- 不改插件模块的内部结构，只合并平台文件。
- 不调整任何播放、曲库、缓存行为。
- proposal 列出的非目标（发布 Release、明文 HTTP 等）。

## Decisions

### 决策 1：插件平台文件合并为单一实现，用 `git mv` 让真实实现占据中立文件名

把 `index.android.ts` 与 7 个 `*.android.tsx` 用 `git mv` 覆盖到对应的中立文件名，删除空实现。路由文件（`src/app/plugins.tsx` 等）已经只是转发到 `@/plugins/screens/*`，不需要改。这样 `git log --follow` 能追到真实实现的历史，空壳的历史随文件删除。

**作废**：`add-plugin-source-system/design.md` 决策 6（以平台后缀文件切断 iOS 引用链）与决策 7 中「iOS 裁剪后仍为完整播放器」的理由；`docs/architecture.md` 中「插件可裁剪」一节随之改写。

**备选与未采纳的理由**

- **保留平台拆分，只把 `index.ts` 改为也转发真实实现**：两份相同的文件并存，下一个读代码的人要先弄明白为什么有两份。拆分唯一的用途是裁剪，用途没了就应该删。
- **用运行时 `Platform.OS` 判断**：两端行为本来就一致，没有可判断的东西。

### 决策 2：门面去掉 `supported`，消费方删掉对应分支

`supported` 是「当前平台是否有插件」的信号，两端都有之后它恒为 `true`。留着一个恒真的字段，消费方就会保留一段永远走不到的分支。删掉字段，`profile.tsx` 无条件渲染入口，`lyrics-card.tsx` 删掉为 iOS 准备的文案分支。

`PluginsFacade` 类型与 `Plugins` 门面本身保留：它是插件模块对外的唯一出口，核心代码只通过它调用插件，这条边界不随平台变化。

**备选与未采纳的理由**

- **保留字段以备将来某平台不支持插件**：没有这样的平台在规划中，为假设的需求留代码属于过度设计。

### 决策 3：保留「插件实现只能被插件目录内部引用」，撤掉「插件专属依赖不得被核心引用」

ESLint 的两组禁令理由不同：

- **实现模块禁令**的本质是架构边界——核心只依赖门面，插件内部可自由重构而不波及核心。这与平台无关，保留，并把注释里的理由从「iOS 裁剪」改为「门面是唯一出口」。`check-constraints.mjs` 中同一边界的检查也保留，理由同样改写。
- **依赖禁令**（`axios`、`cheerio` 等不得被核心引用）的唯一理由是「随插件一并从 iOS 产物裁掉」。iOS 产物里本来就会带上它们，核心代码引不引用不改变任何东西，因此撤掉。这些库作为「插件可用的第三方库」的兼容契约（README 列出的名单）不受影响。

**备选与未采纳的理由**

- **两组都保留**：依赖禁令会留下一条说不出理由的规则。
- **两组都撤掉**：核心可以直接引用插件实现模块，门面边界名存实亡。

### 决策 4：许可证检查从「禁止 GPL 系」改为「拦下不能与 GPL-3.0-or-later 合并分发的许可证」

约束的本质从「维护者能否替这个库向 Apple 做额外授权」变成「这个库能否和本项目一起按 GPL-3.0-or-later 发布」。按此判定：

| 许可证                                     | 判定 | 理由                                                                 |
| ------------------------------------------ | ---- | -------------------------------------------------------------------- |
| MIT、BSD、Apache-2.0、ISC 等宽松许可证     | 放行 | 与 GPL-3.0 兼容（现状）                                              |
| LGPL、GPL-2.0-or-later、GPL-3.0、AGPL-3.0  | 放行 | 均可与 GPL-3.0-or-later 合并分发；AGPL-3.0 依 GPL-3.0 第 13 条可组合 |
| 仅限 GPL-2.0（`GPL-2.0-only` / `GPL-2.0`） | 拦下 | 与 GPL-3.0 不兼容，这是许可证本身的冲突而不是政策选择                |
| 专有授权（`SEE LICENSE`）、未声明          | 拦下 | 无法确认可以再分发                                                   |

拦下的含义不变：检查失败、需要人工复核，不是绝对禁止。

**备选与未采纳的理由**

- **整条许可证检查删掉**：专有授权与仅限 GPL-2.0 的库仍然会让项目无法合法分发，这一层保护与上架无关。
- **继续禁止 AGPL**：用户选择了全部放开；AGPL-3.0 与 GPL-3.0 可以组合，没有许可证层面的理由拦它。禁止复制 MusicFree 源代码的约束出于版权而非许可证类型，不受影响（见 proposal 非目标）。

### 决策 5：删除整个 `.github/`，分支保护由用户在 GitHub 上撤销

`.github/` 里只有 CLA 一套东西，整目录删除。仓库设置不在代码里，必须由用户操作，并且**要先于或紧随删除工作流的 push**：必需检查 `CLA` 不再有工作流上报状态，PR 会一直停在「等待检查」。

撤销用 `gh api`（需要仓库管理权限）：把分支保护中的必需检查列表去掉 `CLA`，或整体删除 `main` 的分支保护。tasks 中给出命令，由用户执行。

**备选与未采纳的理由**

- **保留工作流但设为不阻塞**：留着一套不再有用的流程和白名单。

### 决策 6：版权行改为 `colinli007 and contributors`

撤掉 CLA 后，外部贡献的著作权留在贡献者手里，维护者不再是唯一版权持有人——「版权人固定写维护者本人」的前提（`gpl-header.js` 注释、CONTRIBUTING 第 28 行）不再成立。版权行改为：

```
// Copyright (C) 2026 colinli007 and contributors · 轻松音乐 EasyMusic
```

它在维护者单独写的文件里同样成立（贡献者集合为空），且不随每次贡献改动文件头。SPDX 行不变。

**作废**：`gpl-header.js` 与 CONTRIBUTING 中「维护者必须始终是唯一版权持有人」「这一行不随贡献者变化是 iOS 合规上架的前提」的表述。

**备选与未采纳的理由**

- **只写 `colinli007`**：有外部贡献后与事实不符。
- **由贡献者在改动的文件里追加自己的版权行**：每个文件的头部会随贡献变得不一致，头部校验规则要改成模糊匹配，收益只是更细的归属记录，git 历史已经提供了。

### 决策 7：README 的「获取方式」只写可以兑现的内容

- **Android**：从 GitHub Releases 下载 APK。首个 Release 尚未发布时，写明「首个版本发布后在 Releases 提供」，不放一个空链接冒充可用入口。
- **iOS**：不上架 App Store，需自行用 Xcode 编译安装，指向「开发」一节；说明免费 Apple ID 签名的应用 7 天后需重新安装。

状态横幅改为功能已完成、两端已验收，同时如实列出已知问题（锁屏无上一首/下一首、其他应用抢占音频后按钮状态不更新），不把它们藏起来。

## Risks / Trade-offs

- **[插件在 iOS 上从未运行过]** → tasks 安排 iOS 模拟器 Release 包上的完整插件验收（安装、搜索、入库、播放、发现、歌词、卸载）。iOS 的 `NSAllowsLocalNetworking` 允许 localhost 明文，现有验收测试服务器可直接使用。
- **[撤掉 CLA 后不能再单方面改许可证]** → 有外部贡献合入后，改用更宽松的许可证需要逐一征得贡献者同意。这是取消 CLA 的直接代价，在 CONTRIBUTING 中写明，用户已接受。
- **[分支保护未撤销导致 PR 卡住]** → tasks 把撤销放在删除工作流的 push 之前，并给出验证命令。
- **[iOS 包体增加]** → 插件宿主与 `cheerio` 等依赖进入 iOS 产物。自行编译安装没有包体审核，可以接受；在 iOS 构建后记录前后体积供参考。
- **[两端 Release 包拒绝明文 HTTP]** → `http://` 的插件地址与音频在两端都不可用。行为一致，不是本次引入的差异，留给另开的 change（proposal 非目标）。

## Migration Plan

1. 用户撤销 `main` 分支保护中的 `CLA` 必需检查。
2. 合入本 change：代码、检查脚本、文档、版权行一次提交，lint、typecheck 与各项检查全部通过。
3. 回滚：`git revert` 即可恢复代码与文档；分支保护需用户手动恢复。
