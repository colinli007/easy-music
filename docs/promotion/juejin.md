# React Native 音乐播放器：把音源、缓存和播放队列拆开

本地文件、远程 URL、插件资源，最后都要进入同一个播放器。真正容易耦合的部分，是地址如何解析、缓存何时生效，以及切换资源后队列如何继续。

**轻松音乐 EasyMusic** 是一个免费、开源、无广告的个人音乐播放器，使用 React Native、Expo 和 TypeScript，支持 Android 与 iOS。它不内置音乐资源，核心工作是组织和播放使用者提供的内容。

当前实现里，有三个值得单独看的边界。

## 1. 缓存命中发生在来源解析之前

播放器不直接区分本地文件、远程地址或具体插件，而是通过统一入口取得可播放资源。

[`src/sources/resolve.ts`](https://github.com/colinli007/easy-music/blob/main/src/sources/resolve.ts)的顺序是：

1. 根据曲目 ID 检查有效本地缓存。
2. 命中时直接返回本地文件地址。
3. 未命中时再查找对应来源，并执行来源解析。

顺序本身就是产品行为：已经保存的文件，不应该为了播放而再次依赖远程来源响应。即使相应插件后来被卸载，入口仍会先尝试可用缓存。

“记录里有缓存”也不等于“文件仍可读”，因此命中判断需要包含文件有效性。播放层拿到统一解析结果后，再负责播放、暂停、定位和切歌。

这个边界不承诺任意曲目都能下载；下载前，来源仍需提供可用内容。

## 2. 播放结束与主动切歌有不同语义

日常使用里，“顺序播放到最后一首结束”和“按下一首”不一定应该产生完全相同的结果。

[`src/playback/queue.ts`](https://github.com/colinli007/easy-music/blob/main/src/playback/queue.ts)集中处理顺序、随机、单曲循环与列表循环模式。[`src/playback/player.ts`](https://github.com/colinli007/easy-music/blob/main/src/playback/player.ts)再把队列决策与实际播放器状态连接起来。

当前代码也处理了两个容易遗漏的细节：

- 顺序播放到队尾自然结束后，保留当前曲目，将进度回到开头并暂停，方便再次播放。
- 从队列移除正在播放的曲目时，按播放模式决定接下来播放哪首，而不是永远取列表中的相邻项。

这些逻辑的价值在于播放行为一致，不适合扩写成“永不出错”或性能提升承诺。对应纯逻辑回归用例在 `src/playback/queue.test.ts` 中，可以沿测试理解各模式的约束。

## 3. 插件能力通过门面进入核心

插件能扩展搜索、发现、导入与歌词，但不应让播放器到处依赖插件内部实现。

项目通过 [`src/plugins/index.ts`](https://github.com/colinli007/easy-music/blob/main/src/plugins/index.ts)暴露核心需要的接口。ESLint 约束外部模块不能直接引用插件实现模块；分层约定记录在 [`docs/architecture.md`](https://github.com/colinli007/easy-music/blob/main/docs/architecture.md)。

因此，不装插件时，本地音乐、音频 URL、曲库与歌单仍可独立使用。安装插件之后，榜单、推荐歌单、专辑、艺人及外部歌单导入等能力按插件的实际支持情况出现。

代码模块边界和运行安全边界是两回事：插件没有隔离沙箱，与应用代码运行在同一个 JavaScript 环境，可以访问网络和应用数据。项目不内置或推荐插件源，使用者需要自行选择可信插件。

## 这些边界如何落到使用体验

当前代码已经把本地批量导入、远程音频地址与 M3U 普通歌单导入接入曲库；支持按歌单、专辑、艺人、已下载查看，歌单内可以长按拖动排序。

歌词按本地目录、内嵌标签、来源插件和歌词插件的顺序尝试查找。有时间轴时逐行高亮，无时间轴时展示文本。最近播放则在成功开始播放后记录，暂停再恢复不会重复累计。

M3U 导入形成的是一份曲库快照，不会跟随源列表自动更新，也不接受 HLS 分片清单。下载所得的长度与内容取决于来源，不承诺整首或无损。
